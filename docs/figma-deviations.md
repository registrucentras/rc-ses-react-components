# Figma deviations

Where the code intentionally differs from the RC Dizaino sistema Figma file
([GPujqQEuxSUKDUPbYmx7TG](https://www.figma.com/design/GPujqQEuxSUKDUPbYmx7TG/RC-Dizaino-sistema)),
the decisions behind it, and questions for the designer. Figma variable bindings are the source
of truth for token choice; where the designer agrees the code is right, Figma is updated to match.

Designer answers to the questions raised up to #250: SAV-7746 (2026-11-18).

## How to use this file

- A PR that deviates from Figma adds a row to Components in the same PR, with status
  `Waiting for designer`. A new question goes into Questions with the next free ID.
- Answers fill the Answer, Code and Figma columns and set the status.
- Code work for agreed items is grouped into iterations: I1 is the next one, I2 a later one.
  An item can start as soon as its answer is agreed and its Figma side is updated.
- The PR that does the code side names the item ID (e.g. "Q6") and marks its Code cell done
  (✅). When both the Code and Figma sides are done or None, the status becomes `Done`.
- `Done` rows are removed with the next library release.

| Status | Meaning |
| --- | --- |
| Waiting for designer | No answer yet |
| Under discussion | An answer is proposed and the other side has not agreed yet |
| Agreed | Agreed; the Code and Figma columns (or the referenced item) say what is left |
| Accepted (Figma follows code) | The deviation stays and Figma is updated to match the code |
| Accepted for now (DS audit) | Stays until the component is audited and, where needed, redesigned to v2 |
| Done | Nothing left on either side |
